# Migration 0.24.0 to 0.25.0

Version 0.25.0 bundles 2 changes:

- **The chief of staff can edit an existing scheduled task.** The chief of staff now knows what to do when the CEO asks to change the times of a scheduled task set up in their Claude app: list the existing tasks, edit the right one in place with the scheduling tool the session has (never a duplicate), and, when the session has no scheduling tool, say so in one sentence and give the steps in the app. Before, the hq only said "No scheduled automation and no hooks", which read as a ban, and the chief of staff told the CEO to use the Claude interface.
- **Optional categories in the CEO todo list.** The CEO todo list (`company/todo.md`) can now group tasks by category, so it reads like a board by type (for example admin, people, follow-up). A category is one optional `#tag` at the end of a task, and the CEO's set lives in an optional `categories:` list in the file's frontmatter. The chief of staff suggests a short default set the first time the CEO asks, tags new tasks when the file has categories, and shows the list grouped by category on request.

No schema version changes: `org.yaml` stays `org/5`, `company/state.md` stays `state/1`.

No schema version changes: `company/todo.md` stays `todo/1` and existing files without categories stay valid. `org.yaml` and `company/state.md` are unchanged.

Apply the sections below in order, all in one commit. In the hq the template placeholders are already rendered, so each edit names a fragment without placeholders. ## 1. The chief of staff can edit an existing scheduled task

Why: the line meant that the framework runs nothing on a schedule, not that the CEO's own scheduled tasks are off limits. The scheduling tools differ by surface (the desktop app can update a task; a session-scoped loop can only be deleted and recreated).

### Edits

#### `CLAUDE.md`

In the section "Session start (always)", replace this line:

```
No scheduled automation and no hooks: everything runs when the CEO opens a session.
```

with:

```
The framework itself runs nothing on a schedule and adds no hooks: its procedures run when the CEO opens a session. A scheduled task the CEO set up in their Claude app is theirs: to change it, list the existing tasks and edit that one in place, never a duplicate (a session `/loop` task has no update: delete and recreate it). With no scheduling tool, say so in one sentence and give the app steps: Code tab, "Scheduled" in the sidebar, open the task, Edit, change the schedule, save.
```

The "Rhythms" line (`Weekly brief, reviews and batched approvals run on demand only, when the CEO asks. No scheduled automation, no hooks.`) stays as it is.

#### `operating-model.md`

In the section "Rhythms (on demand only)", replace this line:

```
No scheduled automation, no hooks. Nothing runs unless the CEO opens a session.
```

with:

```
No scheduled automation, no hooks: the framework runs nothing unless the CEO opens a session. A scheduled task you set up in your Claude app is yours; ask the CoS to change its times and it edits that task in place, or, if the session cannot, tells you the steps in the app (Code tab, "Scheduled" in the sidebar, open the task, Edit, change the schedule, save).
```

Plain summary for the CEO: "If you ask me to change the times of a scheduled task you set up, I find that task and edit it in place. If this session cannot edit it, I tell you the steps in the Claude app."
