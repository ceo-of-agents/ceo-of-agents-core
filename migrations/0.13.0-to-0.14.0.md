# Migration 0.13.0 to 0.14.0

Version 0.14.0 makes the hq easier to read for scripts and front-ends, and safer to run without a person at the keyboard:

- **Each pending item says what it needs.** Every line in "Waiting on the CEO" carries a kind right after the urgency: `{ok}` (the CEO approves, then the chief of staff or a department carries it out), `{do}` (only the CEO can do it) or `{decide}` (a decision card), for example `- ACME-A12 [normal] {ok}: ...`. A front-end can then show the right button, and a script can count what waits without reading the prose.
- **The plugin's own skills are pre-allowed.** `.claude/settings.json` allows `Skill(ceo-of-agents:*)`, so the session start and the other procedures run without a permission prompt, also in a non-interactive run (`claude -p`), where an unapproved skill call is denied.
- **A missing plugin is no longer silent.** A project-scope install is tied to one folder path: in another folder, a fresh clone or another computer, Claude Code starts without the plugin's skills although `.claude/settings.json` enables it. `CLAUDE.md` now says "installed for this project", gives the install command, and tells the chief of staff to say in the status that the plugin is missing, with the fix. Setup checks the install for the new folder before the first commit.
- **Boot-set budgets in bytes, checked by a script.** `schemas/boot-set.md` states every budget in bytes on its own row, and the plugin ships `scripts/check-boot-set.sh`, which measures the boot files, finds long lines in `company/state.md` and reports pending lines without a kind. The session start and the weekly brief report its output instead of doing the arithmetic themselves.
- **Design and brand for visual work only.** Setup no longer suggests a design and brand department to draw the org chart. At the first session the chief of staff offers to draw the org chart itself, from `org.yaml`; a design and brand department, if there is one, can make a polished version for sharing.
- Handoff notes gain one optional frontmatter field, `title`, a short plain-language title.

No schema version changes: `org.yaml` stays `org/5` and `company/state.md` stays `state/1`. The kind is a required part of each pending line from this version on (`schemas/state.md`), and the optional `title` is new in `schemas/handoff.md`.

Apply the sections below in order. In the hq the template placeholders are already rendered, so each edit names a fragment without placeholders, or says which value of this hq to use. Where a fragment is not found exactly (the CEO edited that part), do not guess: show the CEO the current text and the intended result, and ask.

## 1. Kind on pending lines

`company/state.md`, section "Waiting on the CEO": insert the kind between the urgency and the colon of every line other than `- none`, as `- <ORG_ID>-A<n> [<urgency>] {<kind>}: ...`. Change nothing else on the line. Infer the kind where the line makes it clear:

- A `D` code: always `{decide}`.
- An `A` code is `{do}` when the CEO must act somewhere outside this chat: a command to run on their computer (`gh ...`, `claude plugin ...`, `git remote add ...`), a click in a console, store or website, an upload, a signature, a payment, creating a repo or an account, updating or installing the plugin, or an answer only the CEO has (for example "answer the setup question deferred at setup"). This holds even when the line starts with "Approve" (for example "Approve the store listing in the developer console" is `{do}`).
- An `A` code is `{ok}` when the CEO's answer is only a yes and the chief of staff or a department then carries the action out: "approve updating hq from ...", "approve merging the pull request ...", "May I ...", a policy loosening to tighten in `org.yaml`, an archive list, or writes on a protected repo.
- Otherwise do not guess. Leave the line as it is, list each such code in the summary with its text, and ask the CEO one plain question for all of them, for example "For ACME-A7 and ACME-A9: is each an OK that I then carry out, or something you do yourself?". Apply the answers. Until then, the session-start check reports these lines.

If a line goes over 300 characters with the kind, keep it; the session-start check reports it and proposes moving the detail to a linked note.

`CLAUDE.md`, section "The CEO pending list". Insert right after the line `- Urgency is `high`, `normal` or `low`.`, with this hq's org id in place of `ACME`:

```
- Every line carries its kind after the urgency: `{ok}` when the CEO approves and you then carry it out, `{do}` when only the CEO can do it, `{decide}` for a D item. Example: `- ACME-A2 [normal] {ok}: <action> (since YYYY-MM-DD)`.
```

`operating-model.md`, section "The pending list and codes". Replace:

```

```

with:

```
Numbers grow monotonically and are never reused. Each line also says what it needs from the CEO: `{ok}` (approve, then the CoS does it), `{do}` (the CEO does it) or `{decide}` (a decision card).
```

## 2. Pre-allowed plugin skills

`.claude/settings.json` is merged, never replaced:

- If it exists, add `"Skill(ceo-of-agents:*)"` to `permissions.allow` unless it is already there. Create `permissions` or `allow` if missing. Keep every other key and entry (`enabledPlugins`, `attribution`, other rules) as they are.
- If it does not exist, create it with `{ "permissions": { "allow": ["Skill(ceo-of-agents:*)"] } }`.

Claude Code applies this rule only in a folder whose workspace trust prompt was accepted; an hq the CEO already uses interactively is trusted. The write into `.claude/` may raise a permission prompt. If it is denied, do not work around it: stop and list the missing edit, as the `hq-version` skill says. `.claude/settings.local.json` (per computer, not tracked) is not touched.
