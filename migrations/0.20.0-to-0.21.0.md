# Migration 0.20.0 to 0.21.0

Version 0.21.0 bundles two changes:

- **A voice for drafts under the CEO's name.** An agent that drafts a message, a mail or a pull request for the CEO has no way to know how the CEO writes, so every draft needs the same corrections. Now an hq can hold a voice for text that goes out under the CEO's name (messages, mails, Slack, posts, slides, and GitHub pull requests, issues and comments made from the CEO's account). It is separate from `ceo.profile`, which stays how agents talk to the CEO in chat. The voice is never used in chat or in hq files.
  - One optional file, `company/ceo-voice.md` (schema `voice/1`, `schemas/ceo-voice.md`), named by an optional key `ceo.voice` in `org.yaml`. It holds Base, channel deltas with dated examples and audience deltas. Only the CEO changes what it says.
  - A new hidden skill, `draft-as-ceo`, is the chief of staff's (CoS) procedure: pick channel and audience, compose Base, channel, audience, deliver text ready to paste, never send. It also captures corrections (one proposed line, added on a yes) and sets the voice up from 3 to 5 messages the CEO wrote.
  - Departments cannot load skills, so the file explains itself in its first section, and each department agent file gets one sentence that points to it.
  - The weekly brief reports a stale voice, only when `ceo.voice` is set.
- **Contextual tips.** The plugin ships a file of contextual tips, `tips/tips.yaml` (format `tips/1`, `schemas/tips.md`). A tip is a short text plus a phrase the CEO can say to the CoS, shown only when its condition holds. At a normal session start, the `session-start` skill may add one tip as the last line of the status, at most once a day. A front end can read the same file. `org.yaml` gets an optional `tips` key (`show`, `dismissed`) so the CEO can switch tips off or dismiss one. Absent means tips are on and nothing is dismissed. The tips file is read from the installed plugin: no hq edit is needed.

No schema version changes: `org.yaml` stays `org/5` (`ceo.voice` and `tips` are new optional keys, absent by default) and `company/state.md` stays `state/1`. A new file schema, `voice/1`, is opt-in: this migration does not create `company/ceo-voice.md`. `tips/1` is new and lives in the plugin, not in the hq.

Apply the sections below in order, all in one commit. In the hq the template placeholders are already rendered, so each edit names a fragment without placeholders. Where a fragment is not found exactly (the CEO edited that part), do not guess: show the CEO the current text and the intended result, and ask. If an edit's new text is already present (the hq was partly migrated before, or this is a second run), skip that edit silently, without asking: ask only when neither the old nor the new text is found.

## Version

`org.yaml`: `framework_version: 0.20.0` becomes `framework_version: 0.21.0`.

`company/state.md`: frontmatter `framework_version: 0.20.0` becomes `framework_version: 0.21.0`.

## What this changes (show the CEO before applying)

Files of the hq that change:

- `CLAUDE.md`: one row in "What the CEO says and what you do", one bullet in "Skills available", and one sentence in "For department agents" (only when the hq has departments).
- `.claude/agents/<agent>.md` of every department that does not come from the catalog as `own`: one sentence.

Files that do not change: `reader.md`, `worker.md`, every charter, `org.yaml` (apart from `framework_version`; no `ceo.voice` and no `tips` key is added) and `company/ceo-voice.md` (not created).

## 1. `CLAUDE.md` (CEO voice)

a. Section "What the CEO says and what you do". Before the row that starts `| "Close the org" / "reopen the org" |`, add this row:

```
| The CEO asks to draft or reply to something under their name | Use the `draft-as-ceo` skill: the voice is in `company/ceo-voice.md` (`ceo.voice`). |
```

b. Section "Skills available". After the bullet that starts ``- `close-org`:``, add:

```
- `draft-as-ceo`: draft text that goes out under the CEO's name, in their voice.
```

c. Section "For department agents" (only when the hq has departments). At the end of the paragraph, after `Never commit to the hq main branch.`, add this sentence:

```
 When you write text that goes out under the CEO's name (pull requests, issues, comments, posts, messages), read the file named by `ceo.voice` in `org.yaml`, if set, and follow it.
```

## 2. Department agent files (CEO voice)

For each department in `org.yaml` `departments:` whose `from_catalog` is not `own`, edit `.claude/agents/<agent>.md` (the `agent` value names the file). Do not edit `reader.md` or `worker.md`, and never a `from_catalog: own` department (its file lives outside the hq).

Where the file has a "Before working:" paragraph (custom departments), find `Never invent numbers: cite source and date. Respect` and replace it with:

```
Never invent numbers: cite source and date. When you write text that goes out under the CEO's name (pull requests, issues, comments, posts, messages), read the file named by `ceo.voice` in `org.yaml`, if set, and follow it. Respect
```

Where the file has the catalog opening line instead (a line that ends `write files in the org's file language.`), add the same sentence at the end of that line, after a space:

```
When you write text that goes out under the CEO's name (pull requests, issues, comments, posts, messages), read the file named by `ceo.voice` in `org.yaml`, if set, and follow it.
```

Advisory departments (legal, finance, tax, and in a personal hq health, money and paperwork) get it too: they may draft letters under the CEO's name. No agent gets a `Skill` tool.

## 3. Existing files that do not change (CEO voice)

`org.yaml` gets no new line: an hq with no voice has no `ceo.voice` key. `company/ceo-voice.md` is created only when the CEO asks to set up their voice.

Plain summary for the CEO: "I can now draft messages, mails and posts under your name in your own voice. If you want, I set it up from 3 to 5 messages you wrote; nothing changes until you say yes."

## 4. Contextual tips (no hq edit)

None required in an existing hq. The tips file is read from the installed plugin. The `tips` key is added to `org.yaml` only when the CEO asks to dismiss a tip or to turn tips off.

Plain summary for the CEO: "From now on I may add one short tip at the end of the status, with a phrase you can say to me. Tell me if you do not want to see a tip again, or no tips at all."
