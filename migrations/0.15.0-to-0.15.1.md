# Migration 0.15.0 to 0.15.1

Version 0.15.1 removes two permission rules that 0.15.0 wrote into `.claude/settings.json`, because each let more through than intended:

- **`Bash(sh *check-boot-set.sh*)`.** In Claude Code's rules `*` matches any text, spaces and arguments included, so this rule allowed every `sh` command whose text contains `check-boot-set.sh`: a command that runs something else, or a script of that name written anywhere. In effect it allowed any shell command without a prompt. It is removed and not replaced: the boot-set check now asks once when the session start runs it. An exact rule would have to name the plugin's install path, which differs per computer and changes with every version.
- **`Bash(git rev-list *)`.** `git rev-list --output=<file>` writes a file anywhere on the computer. It is replaced by the exact form the session start runs, `Bash(git rev-list --count HEAD)`.

The plugin's `gates/permissions.md` lists both under "Retired rules", and its CI check now fails on any rule with a wildcard in a command that starts a shell or an interpreter, in the rule table and in the plugin's skills. The skills `session-start`, `weekly-brief` and `init-fleet` no longer pre-allow the boot-set check, and `init-fleet` no longer pre-allows `python3 -c`, `ruby -ryaml` or `ruby -rjson`: Claude Code asks before each.

An hq that applied `0.14.0-to-0.15.0` with plugin 0.15.1 or later already has the corrected rules: for it this migration only bumps the version. No schema changes: `org.yaml` stays `org/5` and `company/state.md` stays `state/1`.

Apply the sections below in order. Where a fragment is not found exactly (the CEO edited that part), do not guess: show the CEO the current text and the intended result, and ask.
