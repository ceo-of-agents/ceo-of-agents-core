# Migration 0.15.0 to 0.15.1

Version 0.15.1 narrows the permission rules that 0.15.0 introduced. An allow rule allows whatever its `*` stands for, and an `ask` rule cannot reliably take part of it back. So no allow rule may now have a `*` that can carry a shell, an interpreter, a file write, a git option that runs a program or writes a file, or a write on GitHub (`gates/permissions.md`, section "Never allowed"):

- **Rules removed from `allow`.** `Bash(sh *check-boot-set.sh*)`, with no replacement: the boot-set check now asks when it runs. `Bash(git rev-list *)` becomes `Bash(git rev-list --count HEAD)`, the form the session start runs. `Bash(gh auth status *)` becomes `Bash(gh auth status)`. The allow rules of the issues, comments, pull-requests and tracker groups, for example `Bash(gh issue create -R <slug> *)` and `Bash(gh project item-add <number> --owner <owner> *)`, are removed.
- **Writes on GitHub ask.** Issues, comments, pull requests and Project items stay free in the gates, but Claude Code now asks before each one. Its prompt shows the repo and the whole text. The skills write them with one `-R <slug>` right after the subcommand and the text inline in single quotes, never `--body-file` or `-F`.
- **`ask` rules unchanged.** Pushes, merges, releases, settings, secrets, deletes, `gh api` and every write on a protected repo still always ask.
- **Skills.** Their `allowed-tools` follow the same list, so they no longer pre-allow:
  - the boot-set check;
  - `git -C <path> ...`;
  - the wildcard forms of `git pull`, `git log`, `git diff`, `git push` and `git rev-list`;
  - GitHub writes;
  - `cp`, `python3 -c` and `ruby -r...` during setup.

  Plain `git log`, `git diff` and `git show` stay prompt-free as Claude Code's own read-only commands. The plugin's CI check now fails on any rule from that list in the rule table, in the generated lists and in the skills.

No schema changes: `org.yaml` stays `org/5` and `company/state.md` stays `state/1`.

## 2. Plugin-only changes (no hq edit)

- The boot-set check (`session-start` step 4, the weekly brief, the setup checks) asks before it runs. Approve it, or deny it: the session start then says `Boot check skipped` and continues.
- Issue, comment, pull request and Project writes ask before each one. The skills write them with `-R <slug>` right after the subcommand and the text inline in single quotes, so the prompt shows the repo and the whole text. A prompt is not a gate's OK: these writes stay free and need no A item.
- Commands on another clone (`git -C <path> ...`: the policy check, the portfolio steps, setup in another folder) and `git push` from the skills ask before each one.
- During setup, Claude Code asks before `cp` and before the `python3` or `ruby` commands that check that `org.yaml` and `.claude/settings.json` parse.

In the summary to the CEO, add two plain lines: some permission rules from 0.15.0 allowed more than the gates meant, and they are now narrower; and Claude Code now asks before the boot-set check and before each write on GitHub (issues, comments, pull requests), which stay free in the gates.
