# Migration 0.17.0 to 0.18.0

Version 0.18.0 bundles two changes:

- **Deny or ask for destructive commands.** Since 0.16.0 the permission rules write a deny baseline (force push, remote branch deletion, history rewrites, `git clean` with force, `gh repo delete`, `gh release delete`, `gh api` DELETE). A deny rule also refuses a command the CEO has explicitly approved, and a front end that drives `claude -p` has no `!` prefix to run it by hand. Agents cannot move the rules themselves, and a hand edit was undone by the next "Write the rules". Now `org.yaml` has an optional `gates.destructive`: `deny` (the default, also when absent) or `ask`. With `ask`, "Write the rules" puts the baseline in `permissions.ask` instead of `permissions.deny`: every such command prompts in every mode, and the actions stay in the `ok` tier, so the CEO's OK still comes first. Setup asks once, in plain words (`init-fleet`, question 7); the answers file takes an optional `destructive` key.
- **Held work on the pending list.** "Waiting on the CEO" listed only approvals, actions and decisions. Open work that the chief of staff (CoS) held instead of routing it (cost, priority, capacity) lived only in issues and initiative pages: the CEO did not see it, and nothing started. Now each piece of held work (not started, not assigned) gets one `{ok}` item, `start <issue or task>, <who would do it>`; the CEO's OK starts it. Work already routed and running is not listed. The `intake` and `record-decision` skills add the item in the same turn when they open an issue or a follow-up and do not route it; the `weekly-brief` hygiene reports open issues in registered repos with no running work and no pending item.

No schema version changes: `org.yaml` stays `org/5` (`gates.destructive` is optional; absent means `deny`), and `company/state.md` stays `state/1` (the new item is an ordinary `{ok}` line).

Apply the sections below in order, all in one commit. In the hq the template placeholders are already rendered, so each edit names a fragment without placeholders. Where a fragment is not found exactly (the CEO edited that part), do not guess: show the CEO the current text and the intended result, and ask.

## 1. Deny or ask for destructive commands

### 1.1 `org.yaml`: keep the hq's current choice

Read `.claude/settings.json`. If every rule of the deny baseline (`gates/permissions.md`, "Never, in any mode", the groups marked `deny`, 35 rules) is in `permissions.ask` and none of them is in `permissions.deny`, the CEO has already moved the baseline to `ask`: set `ask`. Otherwise set `deny`. If the baseline is split between the two lists, show the CEO which rules are where and ask which to set.

In the `gates:` block, after the line that starts with `  ok:`, add (with the value found above):

```
  destructive: deny   # deny | ask: destructive commands (force push, deletes, history rewrites) refused, or asked every time
```

### 1.2 `.claude/settings.json`

Run "Write the rules" (`gates/permissions.md`) with the new key. With `ask`, the baseline stays in `permissions.ask` and is not added back to `permissions.deny`; with `deny`, nothing changes.

### 1.3 `operating-model.md`

Section "Permission rules". Replace:

```
and `git reset --hard` always asks; you can run them yourself in a terminal outside Claude Code.
```

with:

```
and `git reset --hard` always asks; you can run them yourself in a terminal outside Claude Code. With `destructive: ask` under `gates:` in `org.yaml`, they ask instead of being refused: an agent still needs your OK first, but a prompt you approve by mistake runs the command, and some cannot be undone.
```

### 2.3 List the held work

In `company/state.md`, "Waiting on the CEO": for each piece of open work the CoS holds (an open issue in a registered repo, a follow-up in a decision record or an initiative page, with no department working on it and no pending item), add `- <ORG_ID>-A<n> [urgency] {ok}: start <issue or task>, <who would do it> (since YYYY-MM-DD)` and increment `next_action`.
